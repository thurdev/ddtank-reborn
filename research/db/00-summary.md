## Postgres port notes (SQL Server specifics found in these DBs)

Feature counts (files containing the construct, procs+views+functions): Player34 — BEGIN TRAN 59, ROLLBACK 60, @@ERROR 122, RETURN 141,
OUTPUT params 51, @@IDENTITY/SCOPE_IDENTITY 35, temp tables (#t) 14, TOP 15, WITH(NOLOCK) 12, dynamic SQL 5, cursors 2, ROW_NUMBER 2.
Game34 — mostly `SELECT * FROM X` loaders (RETURN 39, @@ERROR 28, ISNULL 31, dynamic SQL 4). Db_Membership — OUTPUT 20, SET ROWCOUNT 1.

- **Plan: don't port procs 1:1.** ~80% of Game34 procs are `SELECT * FROM <table>` loaders → replace with Drizzle queries in packages/game-data.
  Player34 procs carry real logic (register, login, item add/update, mail send with attachments, auction, guild ops) → port to TS service functions
  inside a transaction, mirroring each proc's return codes.
- **Return codes**: C# reads `@Result`/RETURN_VALUE (`ReturnValue` param) — most Player34 procs `RETURN 0` on success and other ints for
  specific errors (see each proc). Preserve these codes; the client messages depend on them.
- **OUTPUT params** (e.g. `@ItemID int OUTPUT` in SP_Users_Items_Add, @UserID in register/login, @Result in Mem_*) → return values / `RETURNING id`.
- **Identity**: `IDENTITY(1,1)` → `integer GENERATED BY DEFAULT AS IDENTITY`; when importing data with explicit ids, call
  `setval(pg_get_serial_sequence(...), max(id))`. `@@IDENTITY`/`SCOPE_IDENTITY()` → `INSERT ... RETURNING`.
- **datetime** (3.33 ms precision, no TZ) → `timestamp(3)` without time zone (server local time semantics in C#: DateTime.Now). Sentinel dates like
  `1900-01-01` / `2000-01-01` appear as "never" — keep them, don't map to NULL. `GETDATE()` → `now()`/`localtimestamp`; `DATEDIFF(day,a,b)`,
  `DATEADD` → interval arithmetic (watch DATEDIFF counting boundary crossings, not elapsed time).
- **bit** → `boolean` (FOR JSON already exported true/false). C# reads bits as bool; ints-used-as-flags (`IsOpen int`) stay int.
- **nvarchar/varchar/ntext/text** → `text`/`varchar(n)`. Data contains Vietnamese (UTF-16 in nvarchar, mojibake possible in varchar columns
  stored as CP1252 bytes). DB collations: Game34/Player34 `SQL_Latin1_General_CP1_CI_AS`, Db_Membership `Chinese_PRC_CI_AS`
  (SP_Admin_SendMail uses explicit `COLLATE Chinese_PRC_CI_AS`). Case-insensitive: name lookups (nick, username, guild name) must use
  `lower()`/`citext` or ILIKE to match behaviour. Trailing-space-insensitive '=' comparison too.
- Types in use: int/bigint/smallint, bit, datetime, nvarchar/varchar, float (34 cols in Game34: rates/physics), decimal/numeric (few),
  ntext + uniqueidentifier (Db_Membership only). → float = `double precision`, ntext = `text`, uniqueidentifier = `uuid`.
- **TOP n** → `LIMIT n`; `TOP 1 ... ORDER BY NEWID()` → `ORDER BY random() LIMIT 1`. `SET ROWCOUNT` → LIMIT.
- **Multiple result sets / OUTPUT totals**: SP_CustomPage returns the page and the total via an OUTPUT param; check each proc for more than one
  trailing SELECT (C# would read them with NextResult()) and model each as a separate query.
- **Paging**: `SP_CustomPage` / `Sp_Fetch_List` build dynamic SQL from table/where/order strings (SQL-injection prone) → replace with typed queries.
- **Transactions**: pattern `BEGIN TRAN ... IF @@ERROR<>0 BEGIN ROLLBACK TRAN; RETURN n END ... COMMIT TRAN` → `db.transaction()` with thrown
  errors mapped to the same return code.
- **ISNULL** → COALESCE; `+` string concat → `||` (NULL semantics same); `CHARINDEX` → `strpos`; `CONVERT(varchar, date, style)` → to_char;
  `LEN` (ignores trailing spaces) → length(rtrim()).
- **Temp tables / cursors** (14 / 2 procs, Sys_* maintenance & ranking jobs) → CTEs or set-based UPDATE ... FROM.
- **WITH (NOLOCK)** → just drop (MVCC).
- **Table-valued function `dbo.Split`** (comma lists, used by admin send-item & ranking) → `string_to_array`/`unnest`.
- `dbo.*Translation` scalar functions are language lookups used by some loaders — check if referenced before porting.
- Many template tables have **no PK** (Shop, Quest, Quest_Condiction, Quest_Goods, NPC_Info, Game_Map, Ball...). Pick natural keys
  (e.g. Quest.ID, NPC_Info.ID, Game_Map.ID, Ball.ID; Shop.ID) and verify uniqueness when importing; add surrogate ids otherwise.
- Column names are PascalCase with typos baked in (`Condiction`, `Grage`, `BackroundWidht`, `Boold`) — the Flash client/XML depends on
  some of these names via .ashx output, so keep a mapping instead of silently "fixing" them.
